# archive

把飞书的数据原样落到本机，形成一个**只增不改**的原始层。

## 它做什么

每 6 小时从飞书拉三类数据，存成普通 JSON 文件：

| 来源 | 内容 | 命令 |
|---|---|---|
| `tasks` | 未完成的待办（标题、创建时间、成员、链接） | `lark-cli task +get-my-tasks` |
| `agenda` | 最近 7 天的日程（标题、起止时间、组织者、会议链接） | `lark-cli calendar +agenda` |
| `minutes` | 妙记：元数据 + **逐字稿全文**（带说话人名和时间戳） | `lark-cli minutes +search` / `+detail --transcript` |

## 它不做什么

- **不做总结、不做结构化、不建索引。** 这里只是“东西别丢”的那一层。
  从原始层到知识库（每日总结、抽取待办和承诺、人物/主题页）是另一件事，
  等 schema 定下来再做——原始 JSON 原样保存，就是为了到时候不用重新拉。
- **不写飞书。** 只调用查询命令。
- **不碰雷鸟眼镜的数据。** 雷鸟的录音转写在雷鸟云端，手机本地没有，见
  [`../docs/design-notes.md`](../docs/design-notes.md)。

## 存在哪

```
<repo 的上级目录>/glasses-hud-data/
  raw/feishu/
    tasks/<任务guid>/<内容哈希>.json
    agenda/<事件id>/<内容哈希>.json
    minutes/<妙记token>/<内容哈希>.json
    _manifest.jsonl          每次运行的流水
```

每个条目目录下还有一个 `_meta.jsonl`，记录每次运行时这个条目是“新增 / 未变 / 新版本”。

**数据目录在仓库外面。** 仓库是公开的，里面有你同事的名字和会议内容。
脚本会拒绝把数据写进仓库内部（要强制需要 `--force`）。`.gitignore` 里也挡了
`minutes/` `raw/` 等，那是第二道防线。

## 三个设计约束

**只增不改。** 文件按内容哈希命名，用 `wx` 模式写入——已经存在的文件不会被
覆盖。一个待办从“未完成”变成“已完成”，会出现第二个版本文件，旧的留着。

**哈希只算来自飞书的内容。** 拉取时间记在 `_meta.jsonl` 里，不进哈希。否则
每次运行时间都不同，同一个条目会被反复当成新版本存一遍（这个 bug 犯过，
连跑两次才发现：第二次的输出是“新版本 57”而不是“未变 57”）。

**逐字稿的路径以 lark-cli 返回的为准。** `minutes +detail` 会把逐字稿写成一个
文件，并在返回 JSON 的 `data.minutes[0].artifacts.transcript_file` 里给出相对
路径。脚本在一个独立的临时目录里运行它、按返回的路径读回来、然后清掉临时
目录，所以不会有散落的副本。

## 用法

```bash
node archive/feishu-archive.mjs               # 拉最近 7 天
node archive/feishu-archive.mjs --dry-run     # 只看会存多少，不落盘
node archive/feishu-archive.mjs --days 30     # 最多 30 天（lark-cli 按时间搜索的上限）
node archive/feishu-archive.mjs --refetch     # 强制重拉所有妙记逐字稿
```

需要本机已安装并登录 `lark-cli`。

### 跳过已存的逐字稿

每条妙记要单独调一次 `lark-cli`，实测每条约 2.5 秒（它要把整份逐字稿取回来）。
妙记是历史记录，写完基本不变，所以**默认跳过已经存过逐字稿的条目**。跳过的
条件是三个同时满足：存档里有逐字稿、搜索元数据没变、没加 `--refetch`。

实测（30 天窗口，23 条妙记）：

| | 第一次 | 之后每次 |
|---|---|---|
| 妙记 | 拉 20 条，跳过 3 条 | 跳过 23 条 |
| 新增 | 133 | 0 |
| 用时 | 58 秒 | **4 秒** |

如果怀疑某条的逐字稿存早了（比如会议还在进行中就归档了），用 `--refetch`
全部重拉；内容确实变了会存成新版本，没变不会多占空间。

### 注册成计划任务

Windows 上注册成计划任务（每 6 小时，30 天窗口）：

```powershell
powershell -ExecutionPolicy Bypass -File register-archive-task.ps1
```

脚本是幂等的，重复运行只会保留一个任务。**这个 `.ps1` 必须保持纯 ASCII**：
Windows PowerShell 5.1 读不带 BOM 的 UTF-8 文件时用系统编码，中文字符会破坏
字符串和续行符——`register-task.ps1` 也因为同样的原因改成过。另外注释不能插在
反引号续行的中间，否则续行会被打断。

## 已知限制

- **`--days` 上限是 30。** 这是 lark-cli 按时间搜索妙记的范围限制，不是脚本的；
  给更大的数会按 30 处理并提示。想拉更早的要自己改调用方式。所以**越早开始跑
  越好**，开始跑之前的时间补不回来。
- **只存“当前未完成”的待办。** 一个待办完成后，就不会再出现在拉取结果里；
  它的最后一个状态（未完成）留在原始层。完成这个动作本身不会被记录到。
- **归档只保留“当时窗口内”的东西。** 待办和日程都是快照：一个 10 天前创建、
  40 天后开的会，只有在被某个窗口拉到过的情况下才存下来了。
- **妙记逐字稿的读取权限可能变。** 现在能读到全文；飞书如果收紧接口，这里会
  拿到 `null`，其他两类不受影响。
- **跳过是基于“存档里有逐字稿”，不是基于“内容是最新的”。** 如果一条妙记在
  归档之后又被补充了内容，而搜索元数据没变，默认不会发现——需要时用 `--refetch`。
